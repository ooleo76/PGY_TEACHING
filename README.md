## 一句話架構

**三個試算表，每個配一個腳本；其中兩個腳本要部署成網址，一個不用。**

```
① 急救課程 試算表 ── Code_急救課程.gs ──[部署]── 網址 A ──→ dash-course.html
                            │
                            └─ 需填：學員回饋的 ID

② 技能評估 試算表 ── Code_技能評估.gs ──[部署]── 網址 B ──→ scoring.html
                            │                              assistant.html
                            │                              dash-skills.html
                            └─ 需填：急救課程的 ID

③ 學員回饋 試算表 ── Code_學員回饋.gs ──[不部署，只有選單]
                            └─ 不需填任何 ID
```

**兩組網址不同，不要互相貼錯。** 這是最容易出錯的一點。

## 回答你的四個問題

**1. common.js 的網址填哪個試算表？**
填**技能評估**的。因為它服務的兩個頁面（教師評分單、技能評估儀表板）讀寫的都是技能評估的資料。

**2. 學員回饋有沒有 GAS？**
有，就是 `Code_學員回饋.gs`。但它**不需要部署、沒有網址、不用填任何 ID**——
它只提供試算表上方的「回饋工具」選單，把 Forms 匯出的資料匯進來。
讀取這些資料是急救課程腳本的工作，它用試算表 ID 直接讀。

**3. 急救課程的腳本為什麼要填急救課程的 ID？**
不用填。之前那是我沒交代清楚造成的誤會。
腳本綁在哪個試算表上，就用 `getActiveSpreadsheet()` 直接讀自己，不需要 ID。
**要填急救課程 ID 的是技能評估腳本**——它要跨檔去讀學員名冊。

**4. assistant.html 要不要填網址？**
要。它有自己的 `APP_CONFIG.gasUrl`，填的是**網址 B（技能評估）**，跟 `common.js` 同一組。

## 建置順序

### 步驟 1　建立三個試算表

把 `sheets/` 的三個檔案上傳雲端硬碟，各自**另存為 Google 試算表**：

| 檔案 | 命名為 | 內容 |
|---|---|---|
| `急救課程排班_115學年度.xlsx` | 急救課程 | 舊檔資料已完整匯入 |
| `技能評估_範本.xlsx` | 技能評估 | 空白範本，刪掉黃底範例列 |
| `學員回饋_範本.xlsx` | 學員回饋 | 空白範本，刪掉黃底範例列 |

各自記下試算表 ID。

### 步驟 2　安裝三個腳本

每個試算表 → 擴充功能 → Apps Script → 貼上對應的 `.gs` → 儲存 → 重新整理試算表。

| 試算表 | 貼哪個檔 | 填什麼 |
|---|---|---|
| 急救課程 | `Code_急救課程.gs` | `FEEDBACK_SS_ID` = 學員回饋的 ID |
| 技能評估 | `Code_技能評估.gs` | `COURSE_SS_ID` = 急救課程的 ID |
| 學員回饋 | `Code_學員回饋.gs` | 不用填 |

### 步驟 3　部署兩個腳本

急救課程與技能評估各部署一次，記下**網址 A** 與**網址 B**。
學員回饋不用部署。

> 每次改 `.gs` 都要重新部署（管理部署作業 → 編輯 → 版本選「新版本」），否則線上跑的還是舊版。

### 步驟 4　填三個網頁設定

| 檔案 | 填 |
|---|---|
| `common.js` | 網址 B |
| `assistant.html` | 網址 B |
| `dash-course.html` | 網址 A |

### 步驟 5　初始化與驗收

| 試算表 | 選單 | 做什麼 |
|---|---|---|
| 急救課程 | 急救課程工具 | 統計各場次報名 → 產生應出席名單 → 更新各梯課程下拉選單 |
| 技能評估 | 技能評估工具 | 建立／修復分頁 → 測試名冊連線 → 測試備份信 → 設定每晚自動彙總 |
| 學員回饋 | 回饋工具 | 建立／修復分頁 |

「測試名冊連線」會顯示第一筆的梯次、職級、學年度，一眼看得出有沒有接對。

## 五個網頁各做什麼

| 檔案 | 誰用 | 做什麼 |
|---|---|---|
| `scoring.html` | 你 | 教師評分單：九面向 1–5、安全項、EPA。送出寫入技能評估並寄備份信 |

網址會是 `https://<帳號>.github.io/<repo名>/scoring.html` 這種格式。

## 學員回饋：Forms 匯入流程

每梯次結束後做一次：

1. Forms → 回應 → **在 Excel 中開啟**，下載 xlsx
2. 開啟後選取資料列（含標題列也可以），複製
3. 貼到「學員回饋」試算表的**貼上區**分頁 A2
4. 選單「回饋工具 → 匯入貼上區」，輸入課程名稱與前／後測

系統依「欄位對照」分頁轉進「回饋」分頁，貼上區自動清空。

**題目文字不必完全一致**，用 bigram 相似度模糊比對，實測可正確處理：

| 對照表寫的 | Forms 實際的 | 結果 |
|---|---|---|
| 課程內容對技能提升的幫助 | 課程內容對**急性呼吸道處置**技能提升的幫助 | ✓ |
| 課程對您臨床（或值班）自信心的提升 | 課程對您臨床(或值班)自信心的提升 | ✓ |

匯入前可先用選單「檢查欄位對照」，它會列出每一欄對到 Forms 的哪一題、哪些沒對到。

**去重**：以 `人事號 + 課程 + 測驗別 + 場次` 為鍵，重複貼上會覆蓋不會新增，整包重貼是安全的。

**問卷務必有梯次與場次日期兩題**，否則回饋接不回排班表的場次。

## 其他設計重點

**兩種年度分開。** 學員年度由到院日期決定（PGY1 = 到院後一年），課程年度是 8 月至隔年 7 月。
晚到院者可同時出現在兩個學年度分頁，這是正常的。詳見急救課程試算表的「使用說明」分頁。

**去重與撤銷。** 分數以 `人事號 + 評估日期 + 課程` 為唯一鍵，評語以 `人事號 + 評估日期 + 站別`。
送出時該鍵已存在就覆蓋原列，所以重送安全、改分數重送也會直接更新。
要撤銷用選單「把選取列標為作廢」，不刪除，紀錄保留。

**離線容錯。** 兩張表單送出時先寫進瀏覽器暫存再送，失敗會顯示重送按鈕。

**先畫快取再更新。** 所有頁面開啟時立刻顯示上次資料，背景再抓新的。
後端有 5 分鐘快取、名冊 6 小時。改完想立刻看到用選單「清除快取」。

**不設及格線。** 既有 21 份資料的 EPA 全落在 1–3，任何切分點現在訂都是猜的。
累積 15–20 份後用 GRS 評「2 邊緣」那群人的平均分回推（邊緣回歸法）。
